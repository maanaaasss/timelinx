The **Timelinx** framework refers to a combination of Core + React Bindings + UI Components. Timelinx is more of a mental framework — each layer can be a library on its own.

## Introduction

Timelinx is a **browser-native timeline editor engine and UI toolkit**. It provides everything you need to build video editors, NLEs, and motion graphics tools that run entirely in the browser — no backend, no plugins, no native code.

It consists of multiple layers:

## Terminology

**Timeline:** A sequence of tracks containing clips, aligned to a timecode basis (frames or timecode).

**Dispatch:** A pure function `(state, command) → result` that validates and applies operations to timeline state.

**Invariant:** A rule that timeline state must satisfy. The dispatch engine checks 24 invariant types before applying any operation.

**Transaction:** A batch of operations applied atomically. If any operation fails validation, the entire transaction is rejected.

## Philosophy

### Pure-function dispatch

Every timeline operation is a pure function: `(state, command) → newState`. No mutation, no side effects, no hidden state.

<Callout title="Why pure functions?">
  Same input always produces the same output. This means your timeline state is predictable, testable, and debuggable without mocking or special tools.
</Callout>

### Headless by design

The core engine knows nothing about React, the DOM, or rendering. You can use it with any UI framework — or no framework at all.

- Use `@timelinx/core` alone for headless state management
- Add `@timelinx/react` when you need React bindings
- Add `@timelinx/ui` when you need pre-built components

Each package works independently. Adopt incrementally.

### Validation at dispatch time

The dispatch engine validates every operation against **24 invariant types** before applying it. Catches bugs at dispatch time, not in production.

Overlapping clips, out-of-bounds timecodes, missing assets — all caught before state is modified.

```ts
const result = dispatch(state, command);
if (!result.accepted) {
  // Rejected with reason + message — no partial state
  console.error(`${result.reason}: ${result.message}`);
}
```

### Atomic transactions

Batch multiple operations into a single transaction. If any operation fails validation, the entire transaction is rejected. No partial state.

```ts
const result = dispatch(state, {
  id: 'razor-split',
  label: 'Split clip at frame 150',
  timestamp: Date.now(),
  operations: [
    { type: 'DELETE_CLIP', clipId: clip.id },
    { type: 'INSERT_CLIP', trackId: track.id, clip: leftHalf },
    { type: 'INSERT_CLIP', trackId: track.id, clip: rightHalf },
  ],
});
```

### Free undo/redo

The history stack is built into the core. Push states onto the stack, undo, redo, or jump to any point. No extra libraries needed.

### Serializable state

All state is plain objects — no class instances, no circular references. Serialize to JSON, persist to localStorage, IndexedDB, or send to a server.

```ts
const json = JSON.stringify(state);
const restored = JSON.parse(json);
```

## When to use Timelinx

Timelinx is designed with flexibility in mind. It is not limited to certain usages.

- **Video editors** — build browser-native NLEs with tracks, clips, and playback
- **Motion graphics tools** — timeline-based animation editors
- **Audio editors** — multi-track audio timelines
- **Any time-based UI** — animation sequencers, scheduling tools, etc.

## Quick Example

```ts
import { createTimeline, createTrack, createClip, dispatch, toFrame, frameRate } from '@timelinx/core';

const timeline = createTimeline({ id: 'tl-1', name: 'My Edit', fps: frameRate(30), duration: toFrame(10800) });
const state = createTimelineState({ timeline });

const track = createTrack({ id: 'v1', name: 'V1', type: 'video', clips: [] });
const result = dispatch(state, {
  id: 'add-track',
  label: 'Add video track',
  timestamp: Date.now(),
  operations: [{ type: 'ADD_TRACK', track }],
});
```
